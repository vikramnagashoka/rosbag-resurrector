# v0.5.0 Build Checkpoints

How to verify each sub-feature of the v0.5.0 mega-release locally as it lands.
Updated incrementally as commits go in.

> Branch: `v0.5.0` · Status: in progress · Target version: `0.5.0`

## Quick setup (once)

The v0.5.0 development venv:

```bash
# From the project root
rm -rf /tmp/v050-build && python3.14 -m venv /tmp/v050-build
/tmp/v050-build/bin/pip install --upgrade pip --quiet
/tmp/v050-build/bin/pip install -e ".[dev]"

# Verify install
/tmp/v050-build/bin/resurrector --version    # → 0.4.2 (bumps to 0.5.0 at release)
```

Run the full test suite anytime (excludes vision tests that need `[vision]` extra):

```bash
/tmp/v050-build/bin/python -m pytest tests/ --ignore=tests/test_vision.py
```

Baseline as of v0.4.2: **468 passed, 7 skipped, 8 deselected** in ~21 sec.

## Sub-feature 1.1 — `resurrector demo --download` ✅ shipped (commit `80cf4cd`)

Real-data sample bag downloader. Replaces the synthetic bag's noise frames
with real HKU FAST-LIVO campus footage so the dashboard's CLIP semantic
frame search returns visually meaningful results.

### What to verify

```bash
# Help text renders the new flag cleanly
/tmp/v050-build/bin/resurrector demo --help | head -25

# Run the new tests in isolation
/tmp/v050-build/bin/python -m pytest tests/test_demo_download.py -v
# Expected: 13 passed, 1 skipped (1 oversize-payload test)

# Smoke check the actual download ONLY if you want to spend ~5 min and ~844 MB:
#   /tmp/v050-build/bin/resurrector demo --download
# Idempotent — second run should print "Already downloaded"

# Inspect what shipped:
git show 80cf4cd --stat
```

### What's tested

- File written at `target` path (default: `~/.resurrector/samples/hku2.mcap`)
- Atomic-rename via `.partial` suffix (no half-files left on failure)
- Progress callback fires per chunk, total reflects Content-Length
- Idempotent re-run skips download if file exists with plausible size
- `--force` re-downloads even if file exists
- Size sanity bounds reject HTML redirect pages (too small) without leaving partials
- `urllib.error.URLError` propagates cleanly with partial file cleanup
- `~` expansion works in target paths
- Default URL points at HuggingFace and ends in `.mcap?download=true`

## Sub-feature 1.2 — Export presets ✅ shipped (commit `07beb52`)

Five named bundles for common ML data-prep workflows: `lerobot`, `rlds`,
`training-tabular`, `camera-only`, `multimodal`. Plumbed through the
core layer, the CLI, and the dashboard backend.

### What to verify

```bash
# 1. List presets via CLI
/tmp/v050-build/bin/resurrector export /dev/null --list-presets
# Expected: Rich table with all 5 presets, format/sync/Hz/topics/description columns

# 2. Try a preset on the demo bag
/tmp/v050-build/bin/resurrector demo --full          # generate synth bag if needed
/tmp/v050-build/bin/resurrector export ~/.resurrector/demo_sample.mcap \
    --preset training-tabular -o /tmp/preset_test
# Expected: "Exported to /tmp/preset_test" + "Used preset: training-tabular"
# Inspect: ls /tmp/preset_test → should have synced.parquet, no camera-related files

# 3. Override a preset's value
/tmp/v050-build/bin/resurrector export ~/.resurrector/demo_sample.mcap \
    --preset training-tabular --downsample 25 -o /tmp/preset_override
# Expected: same output but at 25 Hz instead of preset's 50

# 4. Hit the dashboard API
/tmp/v050-build/bin/resurrector dashboard &
DASHBOARD_PID=$!
sleep 3
curl -s http://localhost:8080/api/export-presets | python3 -m json.tool | head -30
# Expected: JSON array of 5 entries, each with name/format/sync/.../available
kill $DASHBOARD_PID

# 5. Run the new tests
/tmp/v050-build/bin/python -m pytest tests/test_export_presets.py tests/test_api_export_presets.py -v
# Expected: 35 passed (28 unit + 7 API integration)
```

### What's tested

- **PRESETS registry shape** — all 5 names present, frozen dataclass, format/topic-filter values valid, name field matches dict key
- **`resolve_preset()` merge logic** — user flags always override preset values; missing user values fill from preset; no preset returns user values with sensible defaults; unknown preset raises `ValueError` listing available names
- **`apply_topic_filter()`** — `None` returns all topics; `"images"` filters to only image topics; `"non-images"` excludes them; unknown filter raises
- **End-to-end via `BagFrame.export(preset=...)`** — produces parquet output for `training-tabular`; excludes camera topics correctly; user override (e.g., `downsample_hz`) takes precedence; unknown preset raises `ValueError`
- **CLI** — `--list-presets` short-circuits and exits cleanly; `--preset NAME` runs end-to-end; unknown preset name exits non-zero
- **API** — `GET /api/export-presets` returns all 5 with required fields + `available` flag reflecting `[all-exports]` install state; `POST /api/bags/{id}/export?preset=…` runs export; user-supplied query params override preset; unknown preset → 400

## Final ship checklist

When all sub-features are merged, verify before tagging `v0.5.0`:

```bash
# 1. Full test suite green
/tmp/v050-build/bin/python -m pytest tests/ --ignore=tests/test_vision.py

# 2. Slow tier (memory regression) green
/tmp/v050-build/bin/python -m pytest tests/test_streaming_oom.py -m slow

# 3. Wheel install in a clean venv (smoke test)
rm -rf /tmp/v050-smoke && python3.14 -m venv /tmp/v050-smoke
/tmp/v050-smoke/bin/pip install --upgrade pip --quiet
cd /tmp && python3.14 -m build /Users/.../rosbag-analyzer
/tmp/v050-smoke/bin/pip install /path/to/built/wheel
/tmp/v050-smoke/bin/resurrector --version    # 0.5.0
/tmp/v050-smoke/bin/resurrector doctor

# 4. Frontend builds cleanly
cd resurrector/dashboard/app && npm ci && npm run build

# 5. Help text renders for every command (no missing flags, no Rich-eaten brackets)
for cmd in scan info health list export diff tag quicklook watch \
           export-frames index-frames search-frames dashboard doctor demo \
           bridge playback bridge live; do
  /tmp/v050-build/bin/resurrector $cmd --help > /dev/null 2>&1 || \
    echo "BROKEN: $cmd"
done

# 6. CHANGELOG is final, version bumped in pyproject.toml + __init__.py
grep -n "0\.5\.0\|0\.4\.2" pyproject.toml resurrector/__init__.py CHANGELOG.md

# 7. PR opened, CI green, then tag
git push origin v0.5.0
# After PR merges to main:
git checkout main && git pull
git tag -a v0.5.0 -m "v0.5.0"
git push origin refs/tags/v0.5.0    # triggers PyPI publish + DMG/DEB
```
