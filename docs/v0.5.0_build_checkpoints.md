## Sub-feature 1.4 — Dataset split generators ✅ shipped

`bf.export(split={...}, split_strategy="time"|"random")` produces a
multi-way train/val/test split, one subdirectory per split, plus a
`split_manifest.json`.

Strategies:
- **time** (default) — chronological. First N% of bag time → train, etc.
  Best for time-series; preserves temporal locality so val/test are
  "future" data the model didn't train on. Streams chunk-by-chunk.
- **random** — uniform per-row randomness with a fixed seed (42, deterministic).
  Materializes per-topic; intended for small bags where row independence is OK.
- **stratified** — raises `NotImplementedError` with v0.6 sketch in the message.

### What to verify

```bash
# Try a time-strategy split via CLI
/tmp/v050-build/bin/resurrector demo --full     # generate synth bag if needed
/tmp/v050-build/bin/resurrector export ~/.resurrector/demo_sample.mcap \
    -t /imu/data \
    -o /tmp/v050_split \
    --split train=0.8 --split val=0.1 --split test=0.1
# Expected: 3 subdirs created + split_manifest.json
ls /tmp/v050_split/
cat /tmp/v050_split/split_manifest.json | python3 -m json.tool

# Try random strategy
/tmp/v050-build/bin/resurrector export ~/.resurrector/demo_sample.mcap \
    -t /imu/data -o /tmp/v050_split_rand \
    --split a=0.5 --split b=0.5 --split-strategy random

# Stratified should fail with a clear v0.6 message
/tmp/v050-build/bin/resurrector export ~/.resurrector/demo_sample.mcap \
    -t /imu/data -o /tmp/v050_strat \
    --split train=1.0 --split-strategy stratified
# Expected: red error mentioning "stratified" + "v0.6"; exit code 1

# Run the new tests
/tmp/v050-build/bin/python -m pytest tests/test_splits.py -v
# Expected: 31 passed
```

### What's tested

- **`validate_split_ratios()`** (10 tests) — empty dict, zero/negative/over-one ratios, sum != 1.0, non-string keys, non-numeric values, floating-point tolerance for 10×0.1 case
- **`_cumulative_time_boundaries()`** (4 tests) — 3-way split math, last-boundary float-drift fix, 2-way, insertion-order preservation
- **`split_export(strategy="time")`** (3 tests) — writes 3 subdirs, writes manifest with strategy/duration/ratios/boundaries, each subdir has parquet output
- **`split_export(strategy="random")`** (3 tests) — writes 3 subdirs, manifest records seed + row counts, deterministic across runs (same seed → same row counts)
- **`split_export(strategy="stratified")`** raises `NotImplementedError` with a clear v0.6 message; unknown strategy raises `ValueError`
- **`BagFrame.export(split=...)`** end-to-end — split via the public API, invalid ratios raise via `export()`, preset + split compose (preset's format flows into split_export)
- **CLI** — `--split train=0.8 --split val=0.1 --split test=0.1` works, `--split-strategy random` works, `--split no_equals_sign` exits 2 with clear error, `--split train=notanumber` exits non-zero, stratified strategy exits with clear message

## Sub-feature 2.1 — Multi-bag synchronized playback ✅ shipped

`MultiBagPlayback` wraps N `PlaybackEngine` instances behind one
play/pause/stop/seek/set_speed control surface. Per-bag wall-clock
offsets stagger start times. Topics are namespaced (`<bag_id>:<topic>`)
so PlotJuggler and the cross-bag-overlay UI handle multi-bag streams
out of the box without WebSocket protocol versioning.

CLI integration (multi-bag flag wiring on `bridge playback`) is a
follow-up — the core orchestration layer is shippable as-is and used
programmatically from Python.

### What to verify

```bash
# Run the new tests
/tmp/v050-build/bin/python -m pytest tests/test_bridge_multibag.py -v
# Expected: 14 passed

# Smoke check the API directly (no live bridge needed)
/tmp/v050-build/bin/python -c "
import asyncio
from resurrector.bridge.multibag import BagPlaybackConfig, MultiBagPlayback

async def main():
    mp = MultiBagPlayback(
        configs=[
            BagPlaybackConfig(bag_path='/Users/vikramnagashoka/.resurrector/demo_sample.mcap', bag_id='a'),
        ],
        speed=20.0,
        message_callback=lambda bid, m: print(f'[{bid}] {m.topic} @ {m.timestamp_ns}'),
    )
    print('discovery:', mp.get_discovery_info()['bags'][0]['id'], '->',
          mp.get_discovery_info()['namespaced_topics'][:3], '...')
    await mp.play()
    await asyncio.sleep(0.5)
    await mp.stop()

asyncio.run(main())
"
# Expected: discovery list, then a flood of '[a] a:/imu/data @ ...' lines
```

### What's tested

- **Config validation** — empty configs, empty bag_id, duplicate bag_id, negative offsets all raise with clear messages
- **Construction** — one PlaybackEngine per config, state STOPPED initially
- **Discovery info** — one entry per bag with id/label/offset/duration; namespaced_topics list every topic prefixed by bag_id; empty label falls back to bag_id
- **Topic namespacing** — every emitted message has `topic` rewritten to `<bag_id>:<original>` before the user callback fires
- **Playback control** — play/stop transitions correctly; set_speed propagates to all engines
- **Offset staggering** (real-time timing test) — bag with `offset_sec=0` emits its first message within ~100ms; bag with `offset_sec=0.3` emits its first message at ~300ms (±200ms scheduling slack)

### Known follow-ups (not blocking the release)

- CLI wiring on `resurrector bridge playback --bag a.mcap --bag b.mcap --offset b=2.5`
- BridgeServer integration to expose multi-bag mode over WebSocket
- Built-in viewer (bridge/web/viewer.js) UI for displaying multi-bag streams with per-bag colors

These are all small follow-ups built on top of the orchestration layer just shipped. Tracked in v0.5.1 if not done in v0.5.0.
